Narrator: n8n 3.0 is scheduled for October 2026, and it's a tidy-up release with teeth. Self-hosted n8n will require Docker. If you installed with npm or npx, that road ends. Old nodes are retiring too: Function and Function Item become the Code node, Cron and Interval become the Schedule Trigger, Item Lists splits into Split Out, Aggregate, Sort and Limit, Read PDF becomes Extract from File, Workflow Trigger becomes the n8n Trigger, and the old OpenAI nodes move to the current OpenAI node. Version 1 of the AI Agent node is also going.
Narrator: A workflow that errors on upgrade is annoying. A workflow that runs but does the wrong thing is dangerous — especially if it touches invoices, leads, payroll data, or customer messages. That's why this video isn't a feature tour. It's an audit. Open every workflow, search for the old node names, and write them down before you touch Docker.
Narrator: Step one: export or snapshot every active workflow. Step two: list every workflow that uses Function, Cron, Item Lists, Read PDF, Workflow Trigger, or AI Agent v1. Step three: move self-host to Docker Compose first, on a copy, not on the live server. Step four: migrate one workflow at a time, run it with sample data, and compare the output to the old run. If the output changes and you can't explain why, stop. That's not an upgrade, that's a rewrite you didn't plan.
Narrator: n8n's own conference this month, In The Loop in Berlin on October 13 and 14, put it the right way: production readiness isn't can an agent do this task? It's can this workflow be observed, controlled, and corrected when it doesn't behave? That means guardrails and human-in-the-loop where it matters. Hold probabilistic AI to deterministic rules for routing, approvals, and limits before an action reaches a customer, a database, or a payment. If your workflow can't be paused, logged, and rolled back, it's a demo, not production.
Narrator: Here's the test I use. Turn on error notifications, feed the workflow a bad input on purpose, and watch where it stops. Does it tell you which node broke? Does it leave the bad output out of the client's file? Does it retry in a way you can see? If it fails quietly and still says done, fix that before 3.0, not after. And document each workflow in three lines: what triggers it, what it touches, and who gets paged when it fails. That doc is what saves you at 2 a.m.
Narrator: Don't upgrade live on a Friday. Don't migrate five workflows at once and hope the diff is clean. Don't trust an AI-generated workflow that looks right but uses nodes that don't exist or fields with the wrong names — that's the exact failure mode other builders flagged this week for plain-English-to-n8n tools. Validate against real node schemas, test with sample data, and keep credentials in n8n credentials, never pasted into a node field.
